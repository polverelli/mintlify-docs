Onboard individual customers with KYC verification to enable transactions on the Lumx platform.

## Prerequisites

Before starting the onboarding process, ensure you have:

- API credentials ([Get your API key](/get-started/authentication))
- Customer's personal information ready
- Required documents in digital format (PDF, PNG, or JPEG)

## Onboarding Process

<Steps>
  <Step title="Create Customer Profile">
    Add customer's basic information to the system
  </Step>
  <Step title="Upload Documents">
    Submit identity and proof of address documents
  </Step>
  <Step title="Start Verification">
    Initiate the KYC verification process
  </Step>
  <Step title="Monitor Status">
    Check verification progress and handle any issues
  </Step>
</Steps>

## Step 1: Create an Individual Customer

Start by creating an individual customer profile with their basic information.

```bash
curl -X POST https://api.lumx.io/customers \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "individual",
    "name": "John Doe",
    "taxId": "123.456.789-00",
    "birthDate": "1990-01-01",
    "country": "BRA",
    "email": "john.doe@example.com"
  }'
```

### Required Fields

| Field | Type | Description | Example |
|-------|------|-------------|---------|
| `type` | string | Must be `"individual"` | `"individual"` |
| `name` | string | Customer's full legal name | `"John Doe"` |
| `taxId` | string | Valid tax ID for the country | `"123.456.789-00"` (CPF for Brazil) |
| `birthDate` | string | Date of birth (YYYY-MM-DD) | `"1990-01-01"` |
| `country` | string | ISO 3166-1 alpha-3 country code | `"BRA"` |
| `email` | string | Valid email address | `"john.doe@example.com"` |

### Response

The response includes a `customerId` and a compliance partner link:

```json
{
  "id": "3c90c3cc-0d44-4b50-8888-8dd25736052a",
  "type": "individual",
  "name": "William Default",
  "taxId": "123.456.789-00",
  "link": "https://in.sumsub.com/websdk/p/sbx_aA00bB11cC33dD44",
  "birthDate": "1990-01-01",
  "country": "BRA",
  "email": "william.default@example.com",
  "walletAddress": "0x1234567890123456789012345678901234567890",
  "blockExplorerUrl": "https://amoy.polygonscan.com/address/0x1234567890123456789012345678901234567890",
  "verification": {
    "status": "not_started",
    "level": "standard"
  },
  "transactionLimits": {
    "single": "1000.00",
    "daily": "10000.00",
    "monthly": "100000.00"
  },
  "createdAt": "2021-01-01T00:00:00Z",
  "updatedAt": "2021-01-01T00:00:00Z"
}
```

<Tip>
  Use the `link` field for Sumsub's web interface as an alternative to API document upload.
</Tip>

## Step 2: Upload Required Documents

Individual customers must provide identity verification and proof of address documents.

### Document Requirements

#### 1. Identity Document (Choose One)
- National ID Card (`id_card`) - front and back
- Driver's License (`drivers_license`) - front and back  
- Passport (`passport`) - single page

#### 2. Proof of Address
- Must be dated within last 3 months
- Shows full name and residential address

### Upload Examples

<CodeGroup>
```bash Passport Upload
curl -X POST https://api.lumx.io/customers/{customerId}/documents \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@/path/to/passport.pdf" \
  -F 'metadata={
    "type": "passport",
    "country": "BRA"
  }'
```

```bash ID Card - Front Side
curl -X POST https://api.lumx.io/customers/{customerId}/documents \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@/path/to/id_front.jpg" \
  -F 'metadata={
    "type": "id_card",
    "country": "BRA",
    "side": "front_side"
  }'
```

```bash ID Card - Back Side
curl -X POST https://api.lumx.io/customers/{customerId}/documents \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@/path/to/id_back.jpg" \
  -F 'metadata={
    "type": "id_card",
    "country": "BRA",
    "side": "back_side"
  }'
```

```bash Proof of Address
curl -X POST https://api.lumx.io/customers/{customerId}/documents \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@/path/to/utility_bill.pdf" \
  -F 'metadata={
    "type": "proof_of_address",
    "country": "BRA"
  }'
```
</CodeGroup>

<Info>
  **File Requirements:**
  - Formats: PDF, PNG, or JPEG
  - Maximum size: 50MB per document
  - Documents must be clearly legible and fully visible
  - Both physical (scanned) and digital documents are accepted
</Info>

## Step 3: Start KYC Verification

Once all documents are uploaded, initiate the KYC verification process:

```bash
curl -X POST https://api.lumx.io/customers/{customerId}/verifications \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<Note>
  **Processing Time:** Individual KYC verification is usually completed within minutes, though it may take longer during peak times.
</Note>

## Step 4: Monitor Verification Status

Check the verification progress and results:

```bash
curl -X GET https://api.lumx.io/customers/{customerId}/verifications \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Response Example

```json
{
  "customerId": "3c90c3cc-0d44-4b50-8888-8dd25736052a",
  "status": "not_started",
  "level": "standard",
  "statusReason": {
    "rejectLabels": ["screenshot", "unsatisfactory_photos"],
    "documents": [
      {
        "type": "passport",
        "status": "temporary_rejection",
        "comment": "Screenshots aren't accepted. Please upload a live photo of the document.",
        "rejectLabels": ["screenshot", "unsatisfactory_photos"]
      },
      {
        "type": "utility_bill",
        "status": "temporary_rejection"
      }
    ]
  }
}
```

### Verification Statuses

<CardGroup cols={2}>
  <Card title="not_started" icon="circle-pause" color="#gray">
    Verification hasn't been initiated yet
  </Card>
  <Card title="under_verification" icon="spinner" color="#blue">
    Documents are being reviewed
  </Card>
  <Card title="approved" icon="circle-check" color="#green">
    Customer is fully verified and ready to transact
  </Card>
  <Card title="temporary_rejection" icon="rotate-left" color="#orange">
    Documents need to be re-submitted
  </Card>
  <Card title="final_rejection" icon="circle-xmark" color="#red">
    Customer cannot be verified
  </Card>
</CardGroup>

### Handling Rejections

If rejected, check `statusReason` in the response, upload corrected documents, and restart verification.
